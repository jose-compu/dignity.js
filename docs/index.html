Documentation

dignity.js is a REST-like P2P object API for decentralized JavaScript applications. Synchronize shared objects across browsers with owner authorization, scoped broadcast encryption, and built-in anti-abuse controls.

Lesson 1 — Hello, two peers

A node is one participant. The in-memory adapter wires peers inside one process (tests and learning):

const { DignityP2P, InMemoryNetworkHub, InMemoryNetworkAdapter } = require('dignity.js');

const hub = new InMemoryNetworkHub();
const security = { appPassword: 'my-team-secret', powSteps: 22 };

const alice = new DignityP2P({ nodeId: 'alice', networkAdapter: new InMemoryNetworkAdapter(hub), security });
const bob   = new DignityP2P({ nodeId: 'bob',   networkAdapter: new InMemoryNetworkAdapter(hub), security });

await alice.start();
await bob.start();

await alice.create('notes', { title: 'Hello P2P' }, { id: 'note-1' });
console.log(bob.read('notes', 'note-1')); // replicated automatically

Lesson 2 — Find peers in a room

Use scoped discovery so peers see who is online before collaborating. See also Room discovery.

await alice.joinDiscovery('lobby', { metadata: { nickname: 'Alice' } });
await bob.joinDiscovery('lobby', { bootstrapPeerIds: ['alice'] });

console.log(alice.listPeers('lobby').map((p) => p.peerId));

await alice.create('notes', { title: 'Room note' }, {
  id: 'note-2',
  broadcastScope: 'lobby'
});

Lesson 3 — Only the owner can edit

The peer that calls create becomes ownerId. Others can read but not update unless you add them as collaborators. Details: Object API.

await alice.create('games', { score: 0 }, { id: 'g1' });
await alice.update('games', 'g1', { score: 10 });   // OK
await bob.update('games', 'g1', { score: 999 });    // rejected — Bob is not owner

alice.on('change', (e) => console.log(e.kind, e.collection, e.id));

Lesson 4 — Invite a collaborator

await alice.update('docs', 'd1', { body: 'shared' }, {
  collaborators: ['alice', 'bob']
});
await bob.update('docs', 'd1', { body: 'Bob edited' }); // OK now

Lesson 4b — Verification & publisher trust (v0.13.0)

Bind each collection to the business logic version that produced writes. Peers running different JS bundles are detected via verificationHash + semver (0.N.M). Trust is decentralized: you choose which publisherId is official — no central app store.

  • registerVerification(collection, { code, version, policy, reflective? }) — local rules
  • registerPublisherVerification(publisherId, collection, …) — trust a publisher's official version
  • hashReflectiveLogic(rulesObject) — fingerprint nested functions via fn.toString()
  • Events: verificationmismatch, policyrejected
const rules = {
  max: 100,
  validate(record) { return record.data.points <= 100; }
};

// Publisher declares official timeline-demo 0.13.0
alice.registerPublisherVerification('alice', 'scores', {
  code: rules,
  reflective: true,
  version: '0.13.0',
  dappId: 'timeline-demo',
  policy: 'strict'
});

// Subscriber opts in to alice as official source
bob.registerPublisherVerification('alice', 'scores', {
  code: rules,
  reflective: true,
  version: '0.13.0',
  policy: 'strict'
});

bob.on('policyrejected', (e) => console.warn('rejected', e.reason));

Try it live: verification policies, reflective hashing, publisher trust. Details: Verification policies.

Lesson 5 — Versions and conflicts

Each update increments version. Use expectedVersion or updateWithRetry to avoid overwriting concurrent edits (see Concurrency).

Lesson 6 — Real browsers (PeerJS)

Swap the in-memory adapter for createPeerJSNetworkAdapter and a signaling server. Open the 3D Chess demo or tic-tac-toe demo in two tabs to see live WebRTC sync. See Browser usage and Signaling.

Lesson 6b — Dual-signed resume checkpoints (chess demo)

The 3D Chess demo supports pausing a live game with a co-signed checkpoint: both players sign the same canonical board payload (FEN, move history, tokens) with their seat keys. The resulting resume link embeds the checkpoint in the URL when it fits; otherwise the creating browser stores a local checkpointRef and you must export the portable checkpoint bundle for cross-device resume. 

Flow:
1. Host + joiner play at least one move
2. Either player proposes pause → opponent signs the same checkpoint
3. Copy the dual-signed resume link (or portable bundle if link uses checkpointRef)
4. On a new device: import seat key backup in the lobby, then open the resume link

Broadcast encryption uses scoped appPassword (PBKDF2-hardened since v0.3.0). Resume checkpoints add an independent Ed25519 dual-signature layer on top of the signed game state.

Common mistakes
  • Mismatched appPassword between peers — messages fail to decrypt.
  • Skipping await node.start() — nothing replicates.
  • Using the in-memory adapter in production — use PeerJS instead.
  • Keeping the default password — always set a strong appPassword.

Quick start

Create a node, join a room, and replicate an object between two peers:

Node.js / ESM 
const {
  DignityP2P,
  InMemoryNetworkHub,
  InMemoryNetworkAdapter
} = require('dignity.js');

const hub = new InMemoryNetworkHub();

const alice = new DignityP2P({
  nodeId: 'alice',
  networkAdapter: new InMemoryNetworkAdapter(hub),
  security: {
    appPassword: 'shared-out-of-band-password',
    powSteps: 22
  }
});

const bob = new DignityP2P({
  nodeId: 'bob',
  networkAdapter: new InMemoryNetworkAdapter(hub),
  security: {
    appPassword: 'shared-out-of-band-password',
    powSteps: 22
  }
});

await alice.start();
await bob.start();

await alice.joinDiscovery('main', { metadata: { nickname: 'alice' } });
await bob.joinDiscovery('main', { metadata: { nickname: 'bob' } });

await alice.create('notes', { title: 'hello decentralized world' }, {
  id: 'note-1',
  broadcastScope: 'main'
});

console.log(bob.read('notes', 'note-1'));

await alice.leaveDiscovery('main');
await bob.leaveDiscovery('main');
await alice.stop();
await bob.stop();
In-memory adapter InMemoryNetworkAdapter is for tests and local demos. Production browser apps use createPeerJSNetworkAdapter (see the 3D Chess demo).

Object API

The core API mirrors REST semantics. Each object belongs to a collection. The peer that creates an object becomes its owner — only the owner may update or delete it.

Method Description Authorization
create(collection, data, options?) Create a new object. Returns the normalized record. Creator becomes owner
read(collection, id) Read one object, or null if missing/deleted. —
list(collection, options?) List objects. Set includeDeleted: true for tombstones. —
update(collection, id, patch, options?) Merge patch into object data and increment version. Owner only
updateWithRetry(collection, id, patchFn, options?) Read-modify-write with automatic retry on version conflicts. Owner only
remove(collection, id, options?) Soft-delete the object (tombstone). Owner only

Scoped broadcast

Pass broadcastScope on create/update to select a team or room password namespace:

await node.create('matches', { mode: 'coop' }, {
  id: 'm-1',
  broadcastScope: 'coop:red'
});

Configure per-scope passwords via security.broadcastPasswords.

Room / team discovery

Discover active peers in a named scope (room, team, raid, etc.):

await node.joinDiscovery('team:red', {
  metadata: { nickname: 'alice' },
  heartbeatIntervalMs: 15000,
  ttlMs: 45000
});

const peers = node.listPeers('team:red', { includeSelf: false });

await node.leaveDiscovery('team:red');

PeerGroup gossip (scalable PubSub)

Scale object-update distribution to millions of subscribers per published object while each peer keeps a small, bounded number of active transports. Think decentralized Twitter: you follow 200 accounts (200 multiplexed gossip groups); a popular account can have millions of followers sharing relay load.

Two replication modes

Apps can mix both modes on the same node.

Mode Use case API
Direct mesh Chess players, small teams, owner + collaborators create / update with connectToPeers (unchanged)
PeerGroup gossip Spectators, public feeds, high-fanout read replicas joinPeerGroup + publishToPeerGroup

Architecture

Publisher --fanout=3--> Peer A --relay--> Peer D ...
              \-------> Peer B --relay--> Peer E ...
               \------> Peer C --relay--> Peer F ...
  • Presence — each group reuses scoped joinDiscovery('gossip:{groupId}') as a membership directory.
  • Transport — sendToPeers(envelope, peerIds); not full-mesh broadcast.
  • Relay — subscribers re-forward to fanout random peers until maxHops.
  • Dedup — gossipId cache (TTL-bounded) stops infinite loops.
  • Connection budget — maxActivePeers per group + globalMaxOpenConnections per node.

Core API

await node.joinPeerGroup('spectate:chess:game-1', {
  bootstrapPeerIds: [hostPeerId],
  fanout: 3,
  maxActivePeers: 8,
  maxHops: 64,
  metadata: { role: 'spectator' }
});

await node.publishToPeerGroup('spectate:chess:game-1', 'record:snapshot', {
  collectionName: 'chess-matches',
  record
}, { fanout: 3 });

// Convenience wrapper for local records
await node.publishRecordToPeerGroup('feed:alice', 'posts', 'post-1');

// Custom app events
await node.publishToPeerGroup('feed:alice', 'timeline:update', { id: 'post-1' });

await node.leavePeerGroup('spectate:chess:game-1');

node.listPeerGroupMembers('spectate:chess:game-1');
node.getPeerGroupStats();
// { joinedGroups, seenGossipCount, openConnectionCount, globalMaxOpenConnections }

Inner message types

Relayed inside peer-group:gossip:

Type Purpose
operation Replicated CRUD operation
record:snapshot Late-joiner catch-up
domain:event Signed, versioned write event (auto-published on CRUD when domainEvents: true)
domain:checkpoint Bulk-tier catch-up anchor (lastEventHash, recordCount)
App-defined Custom payloads via publishToPeerGroup (emits peergroupmessage)

Security

  • Group-scoped encryption via existing broadcastScope = gossip:{groupId}.
  • Signatures and PoW verified before relay (same MessageSecurityService path).
  • Invalid gossip rejected; banned peers ignored.
  • record:snapshot gossip carries record.hash (sha512: over canonical data). Receivers recompute locally and reject snapshots whose hash does not match payload data (emits content-hash-mismatch).
  • gossipId dedup cache prevents replay loops across relays.
  • Set relayEnabled: false on a group to receive updates without re-forwarding.

CQRS tiers & query replicas (v0.8+)

For audiences above ~5 000 subscribers per publisher, use the command/query split: publishers write locally and emit signed domain events; subscribers maintain read-only materialized views.

  • Live tier — first liveCap subscribers (default 5 000) receive real-time gossip via publishToPeerGroup.
  • Bulk tier — overflow subscribers receive batched updates via publishPeerGroupBulk and elected bulk relays.
  • Domain events — every create / update / remove on a publisher group auto-emits domain:event with hash-chain linking.
  • Query replica — DignityQueryReplica hydrates local read / list views without contacting the owner.
const { DignityP2P, DignityQueryReplica } = dignity;

// Publisher (command path)
await publisher.joinPeerGroup('feed:alice', {
  role: 'publisher',
  tiered: true,
  liveCap: 5000,
  domainEvents: true
});
await publisher.create('posts', { text: 'hello' }, {
  id: 'p1',
  peerGroupId: 'feed:alice'   // auto-publishes domain:event
});

// Read-only replica (query path)
const replica = new DignityQueryReplica(reader, {
  groupId: 'feed:alice',
  collections: ['posts'],
  publisherId: 'alice'
});
await replica.start({ bootstrapPeerIds: ['alice'] });
replica.read('posts', 'p1');
replica.verifyChain();  // hash-chain consistency

Chess spectators

The 3D Chess demo mixes both replication modes:

  • Players — direct mesh between white/black (low latency).
  • Spectators — joinPeerGroup('spectate:chess:{gameId}').
  • Moves — mover updates on the direct path; also publishRecordToPeerGroup for spectators.
  • New spectator — epidemic relay + host snapshot on join; host does not O(N) connect.

Direct secure messaging

Send end-to-end encrypted messages to a specific peer:

alice.registerPeerPublicKey('bob', bob.getPublicKey());
bob.registerPeerPublicKey('alice', alice.getPublicKey());

await alice.sendDirectMessage('bob', 'dm', { text: 'private payload' });

Optimistic concurrency

Every update carries a monotonic version. Stale operations are rejected when baseVersion does not match. Listen for conflict events or use built-in helpers: 

node.on('conflict', (event) => {
  // event.phase: 'local' | 'remote'
  console.log(event.expectedVersion, event.currentVersion);
});

// Fail fast on stale local writes
await node.update('games', 'g1', { score: 10 }, { expectedVersion: 3 });

// Automatic retry for read-modify-write loops
await node.updateWithRetry('games', 'g1', (current) => ({
  score: current.data.score + 1
}));

Record content hashes

Active records from create, read, list, update, and pushRecordSnapshot include a hash field: 

const record = await node.create('notes', { title: 'hello' }, { id: 'n1' });
console.log(record.hash); // sha512:<128-char hex>
  • Algorithm: sha512 via tweetnacl.hash (browser and Node).
  • Scope: canonical record.data only — not id, owner, timestamps, collaborators, or version.
  • Canonicalization: stableStringify so object key order does not change the digest.
  • Replication: hashes are set on create/update and travel with snapshots.
  • Integrity: restoreRecord recomputes locally; mismatched remote hashes emit warning with type: 'content-hash-mismatch'. Gossip snapshots use strict mode and are rejected on mismatch.

Security model

All security features are enabled by default. Configure via the security constructor option.

Feature Default Details
Signing On Ed25519 signature on every message
Broadcast encryption On AES secretbox; PBKDF2-SHA256 key from appPassword (100k iterations)
Direct encryption On NaCl box (X25519) — true E2E to recipient public key
Proof-of-work On Sloth VDF; default powSteps: 22 (~1s on reference hardware)
Peer bans On Invalid signature or PoW → 48h ban (configurable)
Broadcast mode is not E2E All peers that know the scope password can decrypt broadcast traffic. Use direct mode for sensitive per-peer data.

Security configuration

const node = new DignityP2P({
  nodeId: 'alice',
  networkAdapter,
  security: {
    appPassword: 'shared-out-of-band-password',
    broadcastPasswords: {
      'coop:red': 'red-team-secret',
      'coop:blue': 'blue-team-secret'
    },
    powSteps: 22,
    kdfIterations: 100000,
    banDurationMs: 48 * 60 * 60 * 1000
  }
});

Verification policies (v0.13.0)

Detect when peers run different app logic. Each write carries a verificationHash and optional semver verificationVersion. On ingest, dignity.js compares remote metadata to your local registry and applies a compatibility policy.

What ships in v0.13.0

  • Collection verification — registerVerification (#115–#117)
  • Reflective hashing — hashReflectiveLogic + reflective: true; AST pretty-print canonicalization so equivalent functions hash the same (#123)
  • Publisher trust — registerPublisherVerification; official 0.N.M per publisherId, P2P only (#123)
  • Dignity Apps — manifest dappVersion + logicHash; storedLogic registry for commands
const { hashReflectiveLogic } = require('dignity.js');

const rules = {
  currency: 'USD',
  validateScore(record) {
    return record.data.points >= 0;
  }
};

const { hash, fingerprintList } = hashReflectiveLogic(rules, {
  stripComments: true,
  policy: 'strict'
});

node.registerVerification('ledger', {
  code: rules,
  reflective: true,
  version: '0.13.0',
  policy: 'patch-only'
});

publisher.registerPublisherVerification('alice', 'ledger', {
  code: rules,
  reflective: true,
  version: '0.13.0',
  dappId: 'timeline-demo',
  policy: 'strict'
});

node.on('verificationmismatch', (e) => {
  console.warn('hash drift', e.localHash, e.remoteHash);
});

node.on('policyrejected', (e) => {
  console.warn('rejected', e.policy, e.reason);
});
Policy Behavior on hash mismatch
advisory (default) Accept with warning (verification-hash-mismatch)
strict Reject; emit policyrejected
patch-only Accept when remote semver shares major+minor
minor-and-patch Accept when remote semver shares major
backward-compatible Accept when remote version is older or equal

Playground: strict reject · reflective hashing · publisher trust. Tutorial: Lesson 4b · TUTORIAL.md.

Decentralized trust (no central registry)

Official dapp versions are publisher-scoped, not fetched from a central server. Each peer chooses which publisherId is authoritative for a collection's 0.N.M semver and verificationHash. Writes are signed; ingest checks hash/version against the registry for that sender via registerPublisherVerification(publisherId, collection, …). 

// Official publisher for timeline-demo 0.13.0
publisher.registerPublisherVerification('alice', 'posts', {
  code: rulesWithFunctions,
  version: '0.13.0',
  dappId: 'timeline-demo',
  policy: 'strict'
});

// Subscriber opts in to alice as official source
subscriber.registerPublisherVerification('alice', 'posts', {
  code: rulesWithFunctions,
  version: '0.13.0',
  policy: 'strict'
});

// Dignity App manifest pins official bundle (stored commands enforce on host)
const { manifest } = validateDignityAppManifest({
  id: 'timeline-demo',
  publisherId: 'alice',
  dappVersion: '0.13.0',
  logicHash: 'sha512:…',
  collections: ['posts'],
  storedCommands: [/* … */]
});

IndexedDB persistence

Survive page reloads by persisting replicated object state to IndexedDB:

const { DignityP2P, IndexedDBPersistence } = require('dignity.js');

const node = new DignityP2P({ nodeId, networkAdapter, security });
const persistence = new IndexedDBPersistence({
  dbName: 'my-app',
  collections: ['games', 'matches']  // omit to persist all collections
});

await node.start();
await persistence.attach(node);

// Later
await persistence.detach();

React hooks

Optional integration via dignity.js/react (requires React ≥ 18):

import { useDignity, useCollection, usePeers } from 'dignity.js/react';

function Room() {
  const { node, status, error } = useDignity(config);
  const games = useCollection(node, 'games');
  const peers = usePeers(node, 'room:chess', { includeSelf: false });

  if (status === 'starting') return <p>Connecting…</p>;
  if (error) return <p>Error: {error.message}</p>;

  return (
    <pre>{JSON.stringify({ status, games, peers }, null, 2)}</pre>
  );
}

CI runs Node.js 18/20/22 only — browser rows reflect manual smoke tests on the playground and chess demo. Full matrix: browser-compatibility.md (#91). Production guide: production-runbook.md (#95).

Events

DignityP2P extends EventEmitter. Common events:

Event Payload
change { kind, collection, id } — object created, updated, or deleted
conflict { kind, collection, id, expectedVersion, currentVersion, phase }
peerdiscovered { scope, peerId, metadata }
peerleft { scope, peerId, reason }
message { senderId, targetId, type, payload } — custom decrypted messages
securityerror { senderId, error }
warning { type, ... } — non-fatal issues (heartbeat, persistence, content-hash-mismatch, orphan-operation, etc.)
